# Project instructions

This is an ETHOnline 2026 **Start from Scratch** project. Read `PLAN.md`, `docs/HACKATHON.md` and `docs/AI_USAGE.md` before implementation. The latest MVP removes spending limits and generic infrastructure while retaining Ledger/Privy features for their prize demos.

- Preserve meaningful hackathon history and commit material prompts, specs, plans, AI disclosures and dependency provenance. Do not backdate or squash away the work.
- The owner uses `main` directly. Follow that preference and the session's commit/push authorization.
- All application commands go through the agent. The local UI is only a view-only pie chart: outer actual holdings, thin inner targets with matching colors, ticker/actual/target labels, and lower-left ETH gas balance in ETH/USD with gas rate below in gwei/USD per gas unit. No header, footer or other sections. ETH remains outside allocation slices and weights. Empty wallets show explicitly labeled targets, never fabricated holdings. Display-only Robinhood/Coinbase quotes use the local cached endpoint and stale labels; they never feed trading.
- A user-issued bare `$rebalance` or `/rebalance` requests setup and arming together through the skill, reusing existing setup and requested notifications; no separate arming message is required. Specific setup-only/status/event/stop requests do only their named operation. Preserve recovery/cycle records. Full raw-key launch starts the existing automatic-recovery graph through unresolved/reverted state after successful preflight; no separate recover/acknowledge/stop-start messages are required. Setup-only and deferred signers never enter this path. If the executing agent cannot start an inactive runner because of financial-action restrictions, report an incomplete and unarmed launch; an already active runner is reused and reported accurately. Do not claim setup-only success fulfills a blocked launch or route arming through another agent/schedule.
- Startup orchestration is deterministic in `src/launch.ts`. A user-reviewed Codex prompt hook handles bare `$rebalance`, typed or submitted as the exact Markdown reference to this repository's canonical `skills/rebalance/SKILL.md`, including the exact observed browser-context framing around that complete request. Browser metadata never supplies launch authority. Armed raw-key recovery is automatic after a 30-second stale-send grace; the separate exact `$rebalance recover` command remains explicit intervention. Read `docs/RECOVERY.md`. If the hook already returned a result, the agent must not repeat launch/start/recovery. Scoped prompts and unrelated links do not launch. Use `launch --setup-only` for permitted preparation. Preserve invocation deduplication, newer stop requests and unknown-start reporting. Read `docs/LAUNCH.md`; never trust or trigger the funded hook on the user's behalf, change hook trust/approval settings, or claim desktop hook dispatch from fixture tests.
- Use one existing agent conversation and the project Rebalance skill. The app runs an explicit deterministic graph. Optional Claude MCP events and `/rc`, or native Codex Remote and a five-minute current-chat event heartbeat, sit outside trading. No custom Codex bridge or signing/permission relay is required. Retain undelivered completion/recovery/Ledger/runtime-attention events, report meaningful new events only and do not claim phone delivery from a transport write or scheduled check.

Read `docs/DEMO_PORTFOLIO.md` for the current selection; do not represent the theme as an audited ethical or anti-monopoly screen.

Ledger tracks drift from its saved public address while disconnected, refreshes on connection and prompts through the agent if still needed. Signing requires physical confirmation; connection alone never authorizes it. Defer hardware tests until arrival.

New cycles without a successful swap may retry after their original ten-minute window; legacy records remain conservative. Persist successful-swap evidence before clearing pending through every receipt path. Persist cycle timing across restarts and target edits; reconcile pending receipts before any interval gate. Polling and notification checks never bypass this cadence. Do not represent it as a spending cap or one-transaction-per-hour limit.

Read `docs/EXECUTION_TIMING.md`; event hints never establish receipt/finality or bypass cadence.
