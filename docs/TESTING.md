# Isolated validation

Run `npm test`, or `npm test -- tests/config-lock.test.ts` for selected files. `scripts/run-tests.mjs` creates a fresh system temporary directory (the canonical POSIX `/tmp`, independent of inherited `TMPDIR`) and supplies both `REBALANCE_ROOT_DIR` and `REBALANCE_DATA_DIR` before Node starts the test processes. It pins child temporary-directory variables inside that disposable root, removes inherited wallet selection and private-key defaults and cleans its own directory when the runner exits. Individual fixtures still create their own disposable directories; routing subprocesses must override both ROOT and DATA together.

Configuration captures paths during module evaluation. A static import can therefore initialize those paths before a test body or hook sets its environment. This caused the fixture-contamination incident recorded in [prompt 063](prompts/063-aligned-labels-and-test-isolation.md). The bootstrap prevents that ordering mistake from selecting ordinary app storage. Under `NODE_TEST_CONTEXT`, configuration also rejects missing, relative and non-temporary DATA paths, and non-temporary explicit ROOT paths, before exposing storage paths. Permitted platform temporary bases are independent of arbitrary `TMPDIR` overrides. Canonical path checks reject symlinks that escape temporary storage; nonexistent fixture children remain supported. Direct `node --test` runs must set their explicit temporary environment before startup or fail with the launcher instruction.

The configuration-lock helper takes an explicit directory and imports no configuration, so importing it cannot capture app paths. Tests that write through exported paths assert those paths match their own fixture before any writes. A child-process regression exercises rejected app imports with write methods instrumented, and another verifies static imports receive launcher paths and cleanup occurs. These checks guard accidental test storage selection; they do not sandbox arbitrary test code or establish live trading or hardware behavior.

Lock contention retries a partially written JSON record for a bounded interval without deleting it. A record that remains malformed yields the fixed busy error and stays intact for inspection. Fixture tests cover partial-to-valid ownership, permanent corruption, cancellation and concurrent configuration writers.
