# Test isolation incident — 2026-09-10

During live-settings development, a new static import of the config-lock helper imported `config.ts` before a transaction fixture assigned its temporary data directory. Its module-level paths therefore resolved to the application’s real `.local` directory. Fixture setup overwrote `config.json` and `private-key`; other test cases modified `pending.json` and `last-transaction.json`. The fixture used a public disposable key and mocked RPC, so no live transaction was broadcast by the tests.

The raw-wallet runner had already been stopped with explicit human approval for the fee-guard upgrade. The incident was reported as soon as the isolation failure was recognized, and affected test execution stopped. The original standalone autogenerated key was overwritten. No backup was located in the project’s prior path or relevant temporary archives, and the human confirmed they have no backup. The original signing key was not recovered; the wallet cannot resume signing without it. No replacement key or wallet was silently created.

After explicit approval, the four contaminated files were moved to an ignored local incident directory without reading key material. The original public configuration was reconstructed and verified byte-for-byte against its previously saved SHA-256 checksum, then the already approved $0.05 fee target was retained. The original last-operation record came from the unchanged stopped public status journal. The pending fixture’s wallet and hash were identified, and the pre-incident record showed no pending transaction. Wallet metadata, holdings/status, cycle, recovery and stop records, and other registered wallets’ public control/configuration records were unchanged across restoration. At that stage the original raw wallet remained paused with no active key file. This restored public state, not signing access.

The shared lock helper no longer imports configuration and requires an explicit directory. Transaction tests assert all captured mutable paths belong to their own temporary directory before registering write hooks. Subsequent validation uses temporary ROOT/DATA environment variables before Node starts. A dedicated test launcher and test-process directory guard now reject ordinary application storage before application paths are exposed; see [isolated validation](TESTING.md). Actual validation results are recorded in AI_USAGE.md. No private key is included in source, logs or this report.

The human subsequently authorized removing the unusable raw wallet from the UI and backend while retaining incident evidence, recorded in [prompt 064](prompts/064-remove-unrecoverable-wallet.md). The raw notifier was stopped and verified inactive, its registry entry and stale chat attachment were removed, and wallet-specific public/control state was moved into the ignored incident archive. The contaminated fixture files remain quarantined. Shared app records and the existing Privy and Ledger portfolios were preserved, with their checked public configuration/control records unchanged. The current conversation was connected to the already registered Ledger portfolio without starting monitoring or requesting a signature. The live selector now contains only Privy, Ledger and New portfolio; Ledger remains stopped. Deleting the app entry does not remove the on-chain address or recover its funds.
